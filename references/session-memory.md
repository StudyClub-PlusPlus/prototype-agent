# Session Memory

> 라운드 종결 직전, 종료 보고 **출력 전** 단계로 기록한다.
> 위치: `01-planning/_memory/SESSION-YYYY-MM-DD-NNN.md` (라운드 1건 = 파일 1개, NNN 은 그날 순번)

## 1. 목적

다음 세션(또는 다른 작업자)이 **왜 이렇게 결정됐는지**를 복원할 수 있게 한다.
git 로그는 "무엇이 바뀌었나"를 남기지만 "왜 그렇게 정했나"는 남기지 않는다.

## 2. 형식

```markdown
---
date: 2026-08-15
round: 003
trigger: SRC-0012 (스터디 등록 프로토타입)
---

## 1. 의도
사용자가 무엇을 원했는가. 결정 발화만 짧게 인용한다.
(대화 원문을 길게 옮기지 않는다)

## 2. 판단
에이전트가 어떤 근거로 어떻게 해석했는가.
- 대안이 있었다면 무엇을 왜 택하지 않았는가
- 측정·조사를 했다면 방법과 결과

## 3. 계획
승인받은 변경 계획 요약 (항목 수준)

## 4. 실행
실제로 만든/고친 산출물 목록

## 5. 잔여
- 보존 잔여와 사유
- 다음 라운드가 이어받을 것
```

## 3. 작성 원칙

1. **결정과 근거 중심.** 진행 로그가 아니다
2. 사용자 발화 원문 인용 최소화 — 결정을 바꾼 한 마디만
3. **번복된 결정을 반드시 남긴다.** "처음엔 A로 갔다가 B로 바꿨고 이유는 C" — 이게 가장 값어치 있다
4. 측정으로 정한 숫자는 **측정 방법까지** 적는다. 나중에 재측정할 수 있어야 한다

## 4. 사용자 식별

부트스트랩에서 확인한 작업자 정보를 frontmatter 에 남긴다. 외부 트래커를 쓰지 않으므로
git config(`user.name`·`user.email`)를 근거로 삼는다.
