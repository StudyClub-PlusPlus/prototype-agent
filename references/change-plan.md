# 변경 계획 승인 게이트

> 기존 산출물(Story·Feature·Epic·PRD)을 추가/수정/병합/폐기하는 작업은
> **실행 전에 단일 변경 계획**을 제시하고 사용자 승인을 받는다. 모드별로 쪼개 다시 묻지 않는다.

## 1. 위치

```
모드 판별 → 분석(읽기 전용) → [변경 계획 → 단일 승인] → Ingest → PRD → FS → US → 검증 → PR
                                                        └──────── 무중단 자율 실행 ────────┘
```

- 분석까지는 **읽기만** 한다. 파일 쓰기·커밋은 승인 후
- 승인 하나가 **파일 산출물 라운드 끝까지** 가는 권한이다

## 2. 계획에 반드시 담을 것

```markdown
## 변경 계획

### 1. 트리거
무엇을 받아서 시작하는가 (SRC-#### 또는 명령)

### 2. 신규 Story (N건)
| 임시번호 | 정규문장 | Actor | 모듈 | P | Epic |
|---|---|---|---|---|---|

### 3. 기존 Story 변경 (N건)
| ID | 현재 | 변경 후 | 사유 |
|---|---|---|---|

### 4. 구조 결정
- 신규 Epic: (slug) — 묶을 Story 목록
- 신규 IA 노드: IA-### — 위치
- 신규 Feature: (slug)

### 5. 후행 산출물
- 작성/갱신할 Story PRD 목록

### 6. 영향 범위
- cascade 플래그가 붙을 기존 문서
- 상태가 바뀌는 Story

### 7. 확인 필요값 (있을 때만)
진행 불가한 누락값을 **한 번에 묶어** 질문
```

## 3. 영역 정본 게이트

이번 작업 영역이 `_registry/canonicals.md` 에 정본 등록된 영역이면, 계획에 다음 질문을 **1회** 포함한다:

> 이 변경을 **정본 프로토타입에 반영**할지, **별도 프로토타입으로 분리**할지

정본이 없는 영역은 비적용.

## 4. 승인 처리

| 응답 | 동작 |
|---|---|
| 승인 | 계획 끝까지 무중단 실행 |
| 부분 수정 | 계획 갱신 후 재제시 (실행 안 함) |
| 거부 | 중단. 아무것도 쓰지 않음 |

## 5. 다시 멈추는 시점

- 라운드가 완전 종결된 뒤 사용자가 새 작업을 지시할 때
- 외부 차단 또는 사용자가 명시한 보류
- 진짜 블로킹 누락값 (1회·일괄 질문)

**모드가 바뀐다는 이유로 멈추지 않는다.** Ingest → PRD → FS → US 는 처음 계획에 이미 포함돼 있다.

## 6. 비적용

변경을 만들지 않는 순수 분석·조회·리포트는 계획 없이 바로 수행한다.
