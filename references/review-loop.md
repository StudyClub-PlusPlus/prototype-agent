# 독립 전문가 검증 루프 (확정 전 필수 게이트)

> 작성자의 자가 검증만으로 확정하지 않는다. 초안이 나오면 **작성 맥락과 분리된 리뷰어 3종**을
> 병렬로 돌려 검증 → 수정 → 재검증을 **전 렌즈 합격까지** 반복한 뒤 PR(사람 승인)로 넘긴다.

## 1. 역할 분리

- **리뷰어는 읽기·판정 전용.** 파일을 수정하지 않는다
- **수정은 오케스트레이터(작성자)가 수행.** 지적을 반영하고 다시 돌린다
- 이유: 고친 사람이 검사하면 같은 맹점을 반복한다

## 2. 검증 렌즈 3종

각 렌즈는 독립 서브에이전트 1개. **병렬 기동**한다.

### L1 — 웹 서비스 도메인·UX
- 사용자 여정이 현실적인가. 실제로 그 순서로 행동하는가
- 정보 구조가 찾을 수 있게 돼 있는가
- **상태 누락**: 로딩·빈 결과·오류·권한없음
- 반응형·터치 환경에서 깨지지 않는가
- 문구가 사용자 언어인가 (내부 용어 노출 여부)
- **AC 적합성(도메인 축)**: 합격선이 운영상 옳은가

### L2 — 보안·개인정보·접근성
- 권한 검증이 서버에 있는가 (화면 숨김으로 끝내지 않았는가)
- 수집 개인정보의 목적·보관기간이 명시됐는가
- 입력 신뢰 경계 (클라이언트 값을 그대로 믿지 않는가)
- 색 대비·키보드 조작·포커스 관리
- 로그·에러에 민감정보가 새지 않는가

### L3 — 기획/PM 정합성
- Story 창작 0건인가 (레지스트리 투영 원칙)
- ID 체계·Actor 표기·상태값이 규약과 맞는가
- 숫자에 근거가 있는가
- 문서 간 모순 (PRD ↔ FS ↔ US)
- **AC 적합성(구조 축)**: 테스트 가능·측정 가능하며 DR/NFR 을 커버하는가

## 3. 판정 등급

| 등급 | 뜻 | 합격 영향 |
|---|---|---|
| **HIGH** | 이대로 구현하면 잘못된 것이 만들어진다 | 차단 |
| **MED** | 중요한 누락. 나중에 재작업을 부른다 | 차단 |
| **LOW** | 개선 제안 | 차단 안 함 (PR 본문에 첨부) |

**합격 = 렌즈별 HIGH·MED 0건.** 3개 렌즈 모두 합격해야 종료.

## 4. 리뷰어 출력 포맷

```
렌즈: L1
판정: 불합격
- [HIGH] 목록 빈 상태 미정의 — 검색 결과 0건일 때 화면이 정의되지 않음 (PRD §2)
- [MED] 마감일 지난 스터디에 직접 URL 진입 시 동작 미정 (US 예외 누락)
- [LOW] "신청하기" 문구가 상세와 목록에서 다름
```

- 지적마다 **어디(문서·섹션)** 를 반드시 붙인다
- 추측이면 추측이라고 밝힌다

## 5. 반복 규칙

1. 3렌즈 병렬 실행 → 지적 수집
2. 오케스트레이터가 HIGH·MED 전부 반영
3. **3개 렌즈 전체를 다시 돌린다** (수정이 다른 곳을 깨뜨렸을 수 있음 — 부분 재검증 금지)
4. 전 렌즈 합격까지 반복

## 6. 에스컬레이션 (1회 질문)

아래에만 사람에게 묻는다. 그 외에는 자율로 계속 회전한다.

- 같은 지적이 **연속 3회** 재발 (구조적 문제 가능성)
- 리뷰어 간 판단이 **상충**
- 범위·SoT 변경 등 **사람 결정**이 필요한 사안

## 7. 기록

`_HISTORY.md` 와 PR 본문에 `검증: L1/L2/L3 합격(R3)` 형태로 라운드 수와 함께 남긴다. 잔여 LOW 는 PR 본문에 목록으로 첨부한다.
