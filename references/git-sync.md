# git 원격 동기화 게이트 (멀티 작업자)

> 산출물 레포(`01-planning/` 등)는 여러 작업자가 공유. 다른 작업자가 먼저 push한 커밋이 원격에 있을 수 있으므로, **작업 착수 전·push 전에 원격 최신을 받아 통합하고 그 위에서 동작**한다. **충돌 시 그냥 중단하지 않고, 받아온 최신분을 기준으로 변경을 재적용해 진행**한다.

## 0. 원칙

- **pull-then-operate**: 최신을 받아 통합한 결과를 기준으로 분석·작성·집계한다. stale 로컬 기준으로 작업하지 않는다.
- **중단이 아니라 통합 후 진행**: 충돌은 기본적으로 자동 통합(아래 §3 규칙)으로 해소하고 계속한다. **사람 결정이 꼭 필요한 의미 충돌만** 1회 보고·질문.
- **레지스트리는 대부분 append/행 단위**라 rebase 충돌이 드물고, 나도 남도 보존하는 방향으로 병합 가능. 집계값(합계·분포)은 병합 후 **재계산**한다.

## 1. 라운드 시작 게이트 (파일 쓰기 착수 직전)

분석(읽기)은 먼저 해도 되나, **첫 파일 쓰기 직전**에 반드시:

1. `git fetch origin` (다중 리모트면 전부 fetch)
2. 미커밋 로컬 변경이 있으면 `git stash` (없으면 생략)
3. `git pull --rebase origin <기본브랜치>` — 원격 커밋을 통합 (아직 로컬 커밋 전이므로 rewrite 위험 없음)
4. stash 했으면 `git stash pop` → 충돌은 §3 규칙으로 해소
5. **통합된 최신 파일을 다시 읽어** 그 기준으로 작업 (stale 메모리 기준 금지)

> 분석~작성 사이 시간이 길었으면 쓰기 직전 `git fetch`로 stale 재확인.

## 2. push 게이트 (커밋 후 push 직전)

1. 변경 커밋
2. `git pull --rebase origin <기본브랜치>` — 그 사이 들어온 커밋 흡수 (로컬 커밋이 origin 위로 재배치)
3. 충돌 → §3 규칙으로 해소 후 `git rebase --continue`
4. `git push origin <기본브랜치>` (거부되면 2로 돌아가 재시도 루프)
5. 다중 리모트(origin·curvai 등)는 통합 기준 origin, push는 전 리모트

## 3. 충돌 자동 해소 규칙 (받아온 최신 기준 재적용)

| 대상 | 해소 |
|---|---|
| `stories.md` 표 | **행 단위 병합** — 양측 신규 행 모두 유지. **다른 키면 둘 다 보존**. **같은 `ST-###` 행을 양측이 다르게 수정**하면 = 의미 충돌 → 보고. **양측이 같은 번호를 새로 발급**했으면 나중에 rebase 하는 쪽이 재발급 |
| `_HISTORY.md`·`INDEX.md`·`stories-index.md`·`ia.md` | append/행 단위 — 양측 항목 모두 유지 |
| 요약 카운트(합계·Actor/P 분포 등) | 병합 결과 기준 **재집계** (양측 수치 단순 채택 금지) |
| `viewer/` 등 코드 | 표준 rebase 해소. 양립 가능하면 통합, 불가하면 보고 |

- **재적용 의미**: 받아온 최신분에 이미 내 의도와 같은 변경이 있으면 중복 추가하지 않고, 없으면 최신 위에 내 변경을 다시 얹는다.
- **의미 충돌(보고 대상)**: 같은 Story/필드를 양측이 다른 값으로 동시 수정, 같은 코드 라인 상충 등 — 1회 보고 후 사용자 결정.

## 4. 종료

`fetch → pull --rebase(통합) → 작업 → 커밋 → pull --rebase(흡수) → push`까지 무중단. 게이트 통과 사실·통합한 원격 커밋 유무를 종결 보고·`_HISTORY`에 한 줄 기록.
